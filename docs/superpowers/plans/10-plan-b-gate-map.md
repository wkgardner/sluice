## 1. Scope & non-goals

**In scope (Plan B owns):** the production gate set for pipeline_version
`production-v3.1`; the production `Profile` and its registry entry; detection
against the download server; migration **007** (production satisfaction
columns); the CephFS disk-floor strategy; the config-key surface these gates
require; and the errata items in §4.

**Not in scope (defer):** the API + CLI write path and `sluice doctor` (Plan C,
errata §E); daemon supervision (Plan C, E1); any change to the mock gates or
the `reference-v1` profiles (Plan A, frozen). Two small, principled extensions to
Plan-A surfaces are now approved and carry their own decision records:
`context.resolve_context` + `RunContext` (⚑A / ADR-0006) and the core `Gate`
contract + daemon persist step (⚑B / ADR-0006).

**Invariants that constrain every disposition below** (design §2, HANDOFF §5):
the DB is the only source of truth; control is state-only and the daemon is the
only actor; `gates → core` one-way (production gates live under `sluice/gates/`,
importing `sluice.core`, never the reverse); reconcile stays a pure function of
state; **sluice never deletes files** (ADR-0005); every failure quarantines
(ADR-0002); no production default is ever a code fallback — a missing required
config key is a load-time error.

## 3. Per-stage disposition (the master table)

`production-v3.1` gate set — **EIGHT gates** (the production `globus` stage splits
into `globus_submit` + `globus_verify` per ADR-0006 d.4, making A4's
persist-before-wait structural). In **TRUE execution order** (`Gate.order`; B3 —
never `PIPELINE_GATE_COLUMNS` order, which lists `downloaded` before the
registration it depends on). Every non-disabled gate is mandatory (ADR-0004); a
gate is absent from a run only by `Applicability.DISABLED` or a per-run exclusion.

| order | gate id | name | satisfied_column | needs | produces (`persists`, ⚑B) | applicability |
|---|---|---|---|---|---|---|
| 0 | `experiment` | LabKey experiment creation | `labkey_registered` | () | `experiment_id` → `experiment_id` | REQUIRED |
| 1 | `download` | Download raw lanes (rsync) | `downloaded` | (`experiment`) | `raw_seqs/` | REQUIRED |
| 2 | `checksum` | Verify checksums | `checksummed` | (`download`) | verification log | REQUIRED |
| 3 | `samplesheet` | Generate by-lane samplesheet (NVD tool) | `samplesheet_created` | (`checksum`) | `samplesheet.csv` | REQUIRED |
| 4 | `registration` | Authority-list sample registration | `authority_registered` | (`samplesheet`) | LabKey list rows | **DISABLED** (⚑D) |
| 5 | `nvd` | NVD preprocess (deacon by-lane, `--resume`) | `nvd_completed` | (`samplesheet`) | `nvd-results/` | REQUIRED |
| 6 | `globus_submit` | Submit Globus clump transfer | `globus_submitted` | (`nvd`) | task id → `globus_task_id` | REQUIRED |
| 7 | `globus_verify` | Poll transfer to completion | `clumped_data_backed_up` | (`globus_submit`) | remote copy verified | REQUIRED |

**Not gates** (deliberately): **detection** (it *creates* runs — §8, the daemon's
`insert_run` seam, not a per-run task); **merge** (v3.1 no-op — F-V31 — simply
absent, no column, no gate); **the pre/post-NVD metadata check** (advisory
notification, non-gating — see §4 C5). The NVD `pipeline_started`/
`pipeline_completed` split collapses into the single `nvd` gate: params
generation is a cheap deterministic internal step, and `--resume` (Nextflow
session cache) is the real resume boundary, not a second gate. **Column rename:**
production's two NVD gate columns `pipeline_started` **and** `pipeline_completed`
(PP `poller_state_db.py:39-40`) become sluice's **single `nvd_completed`** column
— downstream plans grepping production for those two names should map both onto
`nvd_completed`.

### Resume-first, per gate (the user principle, made concrete against real code)

- **`experiment`** — reuse `runs.experiment_id` (read from the `RunContext`
  run-row snapshot, ADR-0006 d.3) if already set (idempotent re-entry; ports PP's
  caller-side idempotency `poller.py:1481-1485` **into** the gate); only create
  when absent, and `persists` the id → `experiment_id` (ADR-0006 d.1). Fixes C1
  (see §4). Touches no disk.
- **`download`** — rsync `-avP` skips already-transferred files (PP `:337`);
  re-entry resumes partials. Disk pre-flight (CephFS xattr headroom, fail-open —
  D1) before starting.
- **`checksum`** — re-verify is fast and idempotent (PP `:1601`).
- **`samplesheet`** — `nvd samplesheet generate … --force` overwrites, so
  re-entry is idempotent (PP `nvd_helpers.py:189`).
- **`nvd`** — `nvd run --resume` is harmless on a fresh run and resumes a failed
  one from its last Nextflow checkpoint (PP `nvd_helpers.py:248`); the session
  cache lives in the **local-POSIX** launch dir (D2/A7). Append-mode log (D3).
- **`globus_submit`** — if `globus_submitted` is already set the gate is satisfied
  and never re-runs (the daemon skips a done gate); on first run it submits, and
  `persists` the returned task id → `globus_task_id` **atomically with**
  `globus_submitted` in one `update_run`/`write_txn` (ADR-0006 d.2/d.4). This is
  A4 made structural: a crash after submit can never resubmit a multi-TB transfer.
- **`globus_verify`** — reads `globus_task_id` back from the `RunContext` run-row
  snapshot (ADR-0006 d.3) and polls the task to terminal (`globus task wait`, PP
  `globus_helpers.py:113`); SUCCESS sets `clumped_data_backed_up`. Never
  resubmits.

### Applicability / production profile

The shipped `production-v3.1` profile marks every gate REQUIRED except
`registration` (DISABLED, ⚑D). Disabling a gate satisfies dependents' needs by
absence (ADR-0004 d.2), so `nvd` (needs `samplesheet` only) never waits on
`registration`. A site that does not want Globus excludes both `globus_submit` and
`globus_verify` per-run (`exclude_gate`) or ships a profile variant with them
DISABLED — and then the run completes at `nvd` deliberately, never a silent "final
gate lies" (C4 resolved structurally — see §4).

## 4. Errata in scope — resolutions

Decided here with citations; genuine user forks are recorded as decided flags in
§5.

- **B1 (gate model, 6-vs-8 stages).** Resolved by §3 against the **v3.1** shape:
  eight gates (merge dropped; samplesheet promoted; NVD collapsed to one; Globus
  split into submit + verify per ADR-0006). **E-2/B1 registration identity:** the
  `experiment` gate is LabKey *experiment creation* (produces `experiment_id`);
  the `registration` gate is *authority-list sample registration* (PP
  `authority_registration.py`). They are distinct gates at orders 0 and 4 — not
  the same gate (the errata's core B1 ambiguity, closed).
- **B2 (`experiment_id` chicken-and-egg).** Experiment creation is a **gate at
  order 0**, not a detection-time stamp (creating a real LabKey row must not
  couple the cheap detection sweep to LabKey availability; production also does it
  as processing step 1, PP `:1479`). `experiment_id` is NULL until gate 0 runs;
  downstream gates derive their experiment-scoped workdir from it (⚑A). Rewind
  protection: `set_gate('labkey_registered', 1)` without `force` is already
  refused (control B2, built) because `experiment_id` is a load-bearing output;
  and because rewind is column-clear only and **never** touches `experiment_id`
  (ADR-0005), a reset of gate 0 preserves the id and the resume-first
  `experiment` gate reuses it — so a rewind cannot orphan the LabKey row. The map
  additionally recommends control refuse `reset_gate`/`backtrack` that would clear
  `labkey_registered` (belt-and-suspenders; carry into the control follow-up).
- **B6 (timeout) → resolved as NONE (F-B6).** With merge gone, `merge_timeout_hours`
  is dead code (F-V31), and the merge-incident vector that motivated a timeout is
  gone with it. **Decision (⚑F, F-B6): sluice imposes NO time bounds on any gate**
  — no `Gate.timeout_seconds` field, no in-gate wall-clock bounds, no configured
  bound in Plan A gates. An external tool that times out on its own and returns an
  error still quarantines as an ordinary FAILURE, but sluice mandates nothing. See
  §5 ⚑F for the accepted consequence (a genuinely hung gate blocks the cycle until
  operator intervention).
- **B7 (raw-FASTQ cleanup).** In v3.1 the raw lanes are the **only** on-disk copy
  (merge makes no second copy — F-V31), and `cleanup_raw_fastq_files` is live but
  **uncalled** (PP `poller.py:1077`). Deleting raw would destroy the only copy and
  contradicts ADR-0005 d.1. **Decision (⚑C): NO `reap` gate.** Raw cleanup is a
  manual operator action, out of scope (ADR-0005 d.4 sign-off obtained).
- **C1 (LabKey create non-idempotent/racy).** The `experiment` gate reuses
  `runs.experiment_id` when present (idempotent re-entry). For first creation, do
  **not** adopt "most recent experiment by this user" (PP
  `labkey_client.py:209-215`, which a concurrent same-user experiment poisons);
  instead resolve the new experiment by the folder-name-bearing `Description`
  (which the gate wrote) or the insert response. Fixed in the gate.
- **C2 (overloaded `labkey_project`).** Split the one key into two:
  `labkey_experiments_project` (the `experiment` gate; real value at PP
  `labkey_client.py:102`) and `labkey_authority_project` (the `registration`
  gate; real value at PP `authority_registration.py:242`). Both are required
  config keys with **no** code default — values live only in gitignored
  `config.json`, never in this document.
- **C3 (`fetch_registered_labels` fails open → duplicate LabKey rows).** The
  `registration` gate must fail **closed**: an API error returns `None` (mirror
  `fetch_authority_map`, PP `authority_registration.py:263`), and the gate
  quarantines rather than re-classifying every sample as INSERT (PP
  `:296-300` returns `set()` today). This is the **precondition to enabling
  `registration`** (⚑D).
- **C4 (final gate lies when Globus absent).** Structurally resolved by the gate
  model: `clumped_data_backed_up` is set only on `globus_verify` gate SUCCESS
  (ADR-0002 d.2 — the loop persists SUCCESS, gates never self-stamp). A site that
  skips Globus makes both globus gates DISABLED/excluded, so the run completes
  deliberately at `nvd` — never the unconditional
  `mark_folder_clumped_data_backed_up` of PP `:1630`.
- **C5 (fail-loud LabKey).** Load-bearing LabKey ops fail **loud** →
  `GateOutcome.FAILURE` → quarantine: `experiment` creation failure and
  `registration` failure both quarantine (never the silent-success of PP
  `labkey_client.py:328-330`). The pre/post-NVD **metadata check** stays
  advisory/non-gating (missing samples are a Slack @-mention, not a pipeline
  stop), but on "LabKey unreachable" it must **log loudly**, never pretend "all
  present" silently.
- **D1 (CephFS disk floor).** Port `check_disk_headroom` (PP `poller.py:943-991`)
  behind a config-selected strategy in core: read **both** `ceph.quota.max_bytes`
  and `ceph.dir.rbytes` xattrs from the **quota root** (not the staging subdir),
  all math in bytes, **fail-open** on a missing xattr, **never** `df`/
  `shutil.disk_usage`. Two consumers: the `download` gate's per-run pre-flight and
  the daemon's global disk-floor auto-pause (already wired in Plan A; Plan B
  supplies the strategy). **Headroom multiplier under v3.1:** the pre-drift B7
  "raw + merged coexist transiently" rationale is **gone** — F-V31 establishes
  that merge produces no second on-disk copy, so raw and merged **never** coexist.
  Under v3.1 headroom is retained **solely for NVD/deacon transient outputs**
  (`nvd-results/` produced alongside the raw lanes during the run). Because the
  `2×` evidentiary basis no longer holds, do **not** bake `2` into code: expose
  `disk_headroom_multiplier` as a **required config key with NO code default**
  (the no-default invariant), tuned by the operator against observed NVD transient
  footprint.
- **D2 / A7 (NVD launch dir).** **Highest-risk port item.** The launch dir holds
  the `.nextflow/` session cache that makes `--resume` work; it must be **local
  POSIX**, never CephFS (the os-pool plugin requires it; a CephFS launch dir
  silently no-ops `--resume` and re-runs hours from scratch, PP
  `nvd_helpers.py:263-267`). Make it a **required config key** `nvd_launch_dir`,
  **validated at load** that it is not under `local_staging_dir`, and **never**
  `__file__`-derived (the Plan-A `__file__` ban already holds in core;
  reasserted for the NVD gate).
- **D3 (NVD append-mode log).** Preserve `'a'` + the run banner (PP
  `nvd_helpers.py:288`); reconcile re-enters gates more often than the old loop,
  so a truncating `'w'` would be *more* destructive to the failing run's log.
- **D4 (download ramp).** Port `download_wave_size` / `download_ramp_delay_seconds`
  and `is_connection_blocked_error` backoff (PP `:360`) into the `download` gate —
  Mizzou's sshd blocks on too many simultaneous connections; dropping the ramp
  re-triggers it.
- **D5 (heartbeats + deployment context).** Hours-long gates (`download`, `nvd`,
  `globus_verify`) emit `heartbeat` liveness events (PP `events.py:229`,
  `heartbeat_interval_seconds`) via the core events surface; if the Plan-A events
  module did not land `heartbeat`, Plan B adds it there (core-clean, no gate
  import). Deployment-context fields ride the existing structlog config.
- **D6 (threadpool contextvar landmine).** `download` fans out over a
  `ThreadPoolExecutor`; the wide-event `contextvars` accumulator does **not**
  propagate into workers. The `download` gate must not emit `enrich`/`heartbeat`
  from inside a worker — do per-file bookkeeping by return value, aggregate on the
  main thread. Encode as a test in the download gate's plan.
- **F-supersessions.** **F-V31** governs §2 (merge/samplesheet). **F-B6** governs
  B6 (no time bounds). **F-ADR4:** binary contracts — globus/registration
  exclusion is the remediation path, no runtime optional tier. **F-AUD1:**
  production columns take migration **007+** (the ladder is at 006).

## 5. Decision flags (⚑ — all DECIDED)

Everything else in this map is decided with citations. These six were the genuine
user decisions; all are now stamped.

**⚑A — APPROVED (2026-07-30).** Experiment creation is a gate at order 0, and
`resolve_context` becomes `experiment_id`-aware for production via **reading (b)**
— a name-keyed fallback workdir for gate 0.
Production paths are `{local_staging_dir}/{experiment_id}/{raw_seqs,merged_seqs,nvd-results}`
(PP `_experiment_staging_dir`, `poller.py:1112-1120`); the Globus destination root
comes from a required config key (`globus_destination_root`, no code default —
real value at PP `globus_helpers.py`/config, never in this document).
*Blast radius (named).* `RunContext.workdir` is a **non-optional** `Path`
(`sluice/core/context.py:30`) and the daemon **unconditionally `mkdir`s
`context.workdir` for every gate incl. order 0** (`sluice/core/daemon.py:379-388`),
where `experiment_id` is still NULL.
*Decision:* keep `RunContext.workdir` non-optional; `resolve_context` derives
`workdir = {local_staging_dir}/{experiment_id}` **when `experiment_id` is set** and
falls back to the Plan-A **name-keyed** `{local_staging_dir}/{name}` while it is
NULL — so gate 0 gets a real, mkdir-able workdir it does not use for staging, and
every later gate gets the `experiment_id`-keyed tree. The change is confined to
`sluice/core/context.py`; the unconditional mkdir at `daemon.py:379-388` stays
sound (the path is always non-null). **Keep the `/staging` symlink**
(`.absolute()`, not `.resolve()`) so NVD's by-lane globs resolve on execute nodes
(PP `:1113-1118`). (Interlocks with ⚑B/ADR-0006 d.3, which adds the sealed run-row
snapshot to `RunContext` — the same file — from which `resolve_context` reads
`experiment_id`.)

**⚑B — APPROVED (2026-07-31) via ADR-0006.** Gate outputs persist as declared
typed columns, written with the checkmark. This map aligns exactly with
`docs/adr/0006-gate-output-persistence.md`:
- **Eleventh `Gate` field `persists: Mapping[str, str]`** (GateResult.metadata key
  → `runs` column), default empty (ADR-0006 d.1). Conscious core-contract change:
  the ten-field pin in `tests/test_gate.py:166-178` is updated to eleven citing
  ADR-0006 (same governance as ADR-0002/0004/0005). Gates still only RETURN;
  the daemon stays the sole writer (ADR-0002 intact).
- **Write choreography (d.2):** on SUCCESS the daemon writes the declared outputs
  and the satisfaction column in **ONE `update_run` inside ONE `write_txn`** —
  output and checkmark can never disagree. A declared key **missing from the
  result's metadata on SUCCESS quarantines the run** (fail loud); a non-existent
  `persists` column fails loud via `update_run`'s live whitelist.
- **Read path (d.3):** `RunContext` gains a **sealed (read-only) snapshot of the
  run row**, so a resuming gate reads its own prior tokens (experiment id, globus
  task id) without touching the DB.
- **Globus split (d.4):** the production `globus` stage becomes `globus_submit`
  (persists the task id atomically with its own new column `globus_submitted`) +
  `globus_verify` (reads the id back, polls) — §3 inventory now EIGHT gates, and
  migration 007 carries the extra `globus_submitted` column (§6). Makes A4's
  persist-before-wait structural.
- **Paths are never persisted (d.5)** — derived from config + identity
  (`resolve_context`), consistent with ⚑A.
- **The generic `gate_outputs` table is PARKED, not rejected (d.6)** — revisit
  triggers per the ADR (a non-identity-grade / non-derivable / unbounded output,
  or a third resume token forcing a migration purely for storage). Until a trigger
  fires it is not built; Plan B needs ZERO new output columns beyond
  `globus_submitted`.

**⚑C — APPROVED (2026-07-30).** No automatic raw-FASTQ cleanup — manual operator
action only. sluice ships no deletion gate; `Gate.invalidate` for production gates
is a documented **no-op** (ADR-0005; d.4 sign-off obtained). Any future automatic
cleanup is a consciously approved exception, not a default.

**⚑D — APPROVED (2026-07-30).** `registration` (authority-list) ships **DISABLED**
in `production-v3.1`: modeled as a real gate (order 4) but
`Applicability.DISABLED` in the shipped profile. Enabling it is a profile change,
**gated on the C3 fail-closed fix landing first** (else a transient LabKey read
generates duplicate rows). Dry-run and test-list defaults stay gate-internal.

**⚑E — APPROVED (2026-07-30).** Boundary holds + heartbeats for liveness. A hold
queued during a long gate (`download`/`nvd`/`globus_verify`) lands when that gate
**returns** (stage-boundary latency); `heartbeat` events (D5) provide liveness in
the meantime. Intra-gate cooperative termination via `Gate.terminate` is a later
daemon extension, not v1.

**⚑F — DECIDED (2026-07-31), F-B6 — NO TIME BOUNDS AT ALL**, superseding this
map's earlier in-gate-timeout recommendation. sluice imposes no wall-clock bound
on any gate: no `Gate` contract field, no in-gate bounds, and **no configured
bound in Plan A gates, period.** (An external tool's own `--timeout`-style flag is
not sluice's mechanism; a tool that times out and returns an error still
quarantines as an ordinary FAILURE, but sluice mandates and configures nothing.)
*Accepted consequence, recorded honestly:* under **drive-until-blocked**, a
genuinely hung gate blocks the daemon cycle until operator intervention — and
because graceful shutdown waits for the current gate to return, the escape from a
true hang is `kill -9`. Decided with the merge-incident vector gone (F-V31);
**revisit on a real observed hang.**

## 6. Migration 007 — production satisfaction columns

Following the 005 precedent (gate-column migrations live in core's `db.py`
ladder so `initialize_database` works with `sluice.gates` absent), **migration
007** adds the production satisfaction columns to `runs`, each
`INTEGER NOT NULL DEFAULT 0` (never nullable — reconcile's `WHERE col = 0` must
not meet three-valued logic; the constant default keeps the ALTER legal on a
populated table):

```
labkey_registered · downloaded · checksummed · samplesheet_created ·
authority_registered · nvd_completed · globus_submitted · clumped_data_backed_up
```

Eight satisfaction columns (one per §3 gate), including `globus_submitted` (the
Globus split, ADR-0006 d.4). The produced load-bearing values already have typed
columns from migration 001: `experiment_id`, `globus_task_id` (and
`slack_thread_ts`) — so Plan B adds **zero** new output columns beyond
`globus_submitted` (ADR-0006 consequence). No new column for detection or merge
(neither is a gate); the two production NVD columns collapse into `nvd_completed`
(§3 rename). A shipped migration is never edited; if 007 grows too large it may
split 007–00N, but the layout above is one coherent migration.

## 7. The `production-v3.1` profile

Built with `build_profile("production-v3.1", [...])` (profile.py), listing the
eight gates in TRUE execution order with the §3 applicability. The daemon's
`assemble_registry` unions it with `REFERENCE_PROFILES` (duplicate-key-loud); it
is stamped into `runs.pipeline_version` at detection and frozen thereafter (§8,
design §8). `required_gates(profile)` = the seven REQUIRED gates (registration
excluded by absence) = the completion predicate. Each production gate is a frozen
`Gate` under `sluice/gates/`, its `run`/`invalidate` pure functions of the
resolved context + config, `invalidate` a no-op (⚑C), `persists` declaring any
typed output columns (⚑B), importing `sluice.core` only (dependency-arrow guard).

## 8. Build sequence (which subsystem first)

Ordered so every downstream unit has real state to act on. Each is its own
test-first plan citing this map. **Detection is next.**

1. **Detection (first).** Replace the Plan-A `watch_dir` stub
   (`daemon.detect_new_runs`, lists local subdirs) with production detection:
   rsync `--list-only` against the download server (or `local_source_dir` mode),
   keep folders with a checksum manifest (`md5s.txt`/`.sha256`) **and at least one
   `*001.fastq.gz`** (production's actual `--include` filter, PP
   `poller.py:196`) — not merely "any fastq" — and use **sluice's own `runs`
   table as the new-vs-known baseline**: `insert_run` stamps
   `pipeline_version = production-v3.1` (frozen) once per name. Everything
   downstream needs real runs to exist. **Sequencing caveat:** detection must not
   go LIVE stamping `production-v3.1` until the `production-v3.1` profile registry

2. **CephFS disk strategy (D1)** — shared by the `download` gate and the daemon

3. **Persistence substrate (⚑B / ADR-0006)** — the `Gate.persists` field + the
